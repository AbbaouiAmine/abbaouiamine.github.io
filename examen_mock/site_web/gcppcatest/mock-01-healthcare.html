Question 1 / 60 D3 M1 S2 single D3/M1/S2 · Data Protection and Secrets Management in Google Cloud
EHR Healthcare is migrating its legacy on-premises patient data system to Google Cloud. The system currently uses a proprietary database that needs to be migrated to a fully managed relational database service that supports PostgreSQL. The solution must comply with HIPAA regulations, ensure high availability across multiple zones, and automatically encrypt data at rest. Which service should you choose and how should you configure it?
  • Use Cloud SQL for PostgreSQL. Enable High Availability (HA). Verify that Google-managed encryption keys are enabled by default, which satisfies the requirement for encryption at rest for HIPAA compliance.
  • Use Cloud Spanner. configured with a multi-region instance configuration. Use default Google-managed encryption keys.
  • Use BigQuery with a dataset configured for the US region. Enable authorized views for access control.
  • Use Cloud SQL for PostgreSQL. Enable High Availability (HA) and ensure the instance is in a VPC Service Controls perimeter. Configure Customer-Managed Encryption Keys (CMEK) for data at rest.
Bonne réponse : A
Cloud SQL for PostgreSQL is a fully managed relational database that can be configured for High Availability (HA) across multiple zones. Data is encrypted at rest by default using Google-managed encryption keys, which is sufficient for HIPAA compliance when combined with proper access controls. While Customer-Managed Encryption Keys (CMEK) provide additional control, they are not strictly required unless specified by organization policy.

Question 4 / 60 D1 M1 S3 single D1/M1/S3 · Supporting the Application Design
EHR Healthcare is designing a disaster recovery (DR) strategy for their critical patient management application running on Compute Engine. The RTO is 4 hours and RPO is 1 hour. They want to minimize costs while meeting these targets. Which DR pattern is most appropriate?
  • Hot Standby (Active-Passive) with a fully scaled replica in the DR region.
  • Warm Standby: Maintain a minimum viable version of the environment in the DR region, capable of scaling up.
  • Active-Active: Run full capacity in both regions behind a global load balancer.
  • Cold Surveillance: Create snapshots of disks every hour. In a disaster, create instances from snapshots.
Bonne réponse : D
Cold Surveillance (often just Cold DR or Backup/Restore) fits the 'minimize costs' driver better than Warm or Hot standbys. An RPO of 1 hour can be met by hourly snapshots. An RTO of 4 hours gives enough time to spin up instances from those snapshots. Warm Standby (B) costs more (running instances). Hot Standby/Active-Active (A/D) are comprehensive but expensive and overkill for 4h RTO.
