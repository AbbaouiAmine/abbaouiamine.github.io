Question 1 / 60single
You are designing a high-traffic web application. You want to ensure that if a single zone fails, the application remains available with no downtime. You also want to minimize latency for global users. Which Load Balancer configuration is best?
  • DNS-based Round Robin.
  • Global External Application Load Balancer with backends in multiple regions.
  • Regional External Application Load Balancer.
  • Network Load Balancer with backends in a single zone.
Bonne réponse : B
A Global External Application Load Balancer distributes traffic to the backend instance group closest to the user (minimizing latency). By having backends in multiple regions (and multiple zones within those regions), you achieve high availability and resilience against zonal or even regional failures.
Référence https://cloud.google.com/load-balancing/docs/https

Your finance team wants to prevent any project in the 'Development' folder from provisioning expensive GPU instances (A2, A3 machine types). They want to allow Standard N2 instances. How do you enforce this?

  • Use Organization Policy `compute.restrictMachineTypes`.
  • Use IAM to deny `compute.instances.create`.
  • Use Organization Policy `compute.restrictSharedVpcSubnetworks`.
Bonne réponse : A

Since Quotas are per-project, and the requirement is for a Folder, Organization Policy `compute.restrictMachineTypes` allowing only `n2-*` is the correct hierarchical enforcement tool.
