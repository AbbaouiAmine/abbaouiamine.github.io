Le problème

Les cheat-sheets Docker, Git, Kubernetes, Terraform ou GCP tiennent dans la poche. La commande, elle, doit encore atterrir dans un terminal.

Sans pont

On lit la commande sur mobile, on la retape sur le PC. Un copier-coller cloud sort du LAN, ajoute un compte, et n’est pas conçu pour ça.

Avec Command Bridge

Même Wi‑Fi. Un QR. La commande arrive sur le desktop, prête à coller. Zéro compte, zéro serveur distant.

Comment ça marche

01

Lancer

ZIP portable Windows : runtime Java minimal inclus. Pas d’install Java, pas de droits admin.

02

Scanner

Le QR encode cmdbridge://pair?host&port&token. Le client Flutter stocke le pairing.

03

Envoyer

Dans l’app cheat-sheet, on choisit une commande. sendCommand() part en WebSocket.

04

Copier

Le desktop l’affiche. Copy, ou double-clic dans l’historique (200 entrées, filtrable).

Architecture

Trois modules, un protocole JSON versionné. Pas de backend cloud.

Desktop

Java 21 + JavaFX. Serveur WebSocket :17321, QR ZXing, presse-papiers, historique JSON dans ~/.commandbridge/history.json.

Flutter client

Package réutilisable : scan QR + sendCommand() pour Docker, Git, GCP, Kubernetes, Terraform.

Protocol v1

hello → hello_ack → command | error. UTF-8 JSON. Le texte de commande est une donnée, pas un script à lancer.

{"v":1,"type":"hello","token":"…","appId":"docker","appName":"Docker CheatSheet"}
{"v":1,"type":"command","title":"Start PostgreSQL","command":"docker compose up -d postgres"}

Fonctions

Pairing QR

Token aléatoire 32 bytes. Régénérer le token invalide les nouveaux handshakes.

LAN only

Le serveur refuse les clients hors réseau privé / local.

Historique

Jusqu’à 200 commandes, filtre par app, copie en un clic.

SDK Flutter

Un receiver desktop pour plusieurs apps cheat-sheet.

ZIP portable

jlink + GitHub Actions : artifact Windows prêt à lancer.

MVP honnête

Pas de sync cloud, pas d’exécution distante, pas de SaaS.

Sécurité

Posture d’ingénierie, pas de slogan. Protocol v1 never executes commands on your machine.

Clients réseau privé / loopback / link-local uniquement.

Auth par token QR, comparaison en temps constant.

Régénérer le QR coupe les nouveaux handshakes avec l’ancien token.

v1 : display + copy only. La commande n’est jamais exécutée.

Stack

Java 21 JavaFX WebSocket Gson ZXing jlink / jpackage Flutter mobile_scanner GitHub Actions

Rôle

Conception du protocole v1, receiver desktop JavaFX, client Flutter réutilisable, CI du ZIP portable Windows, et la contrainte explicite : pas d’exécution distante.

Statut : MVP v1 fonctionnel. Case study — pas une landing commerciale.
