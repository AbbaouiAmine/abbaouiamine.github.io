LLM & tokensLLM & tokens

Token

Unité de texte que le modèle lit et génère ; la facturation et la fenêtre de contexte se comptent en tokens. Unit of text the model reads and generates; billing and the context window are measured in tokens.
Documentation officielleOfficial documentation ↗

Context window

Budget fixe de tokens pour prompts, historique, tool results et sortie. Un input trop grand est rejeté ; un dépassement en cours de génération tronque la sortie (stop reason de type context-window exceeded). Fixed token budget for prompts, history, tool results, and output. Oversized input is rejected; overflowing mid-generation truncates output (a context-window-exceeded stop reason).
Documentation officielleOfficial documentation ↗

Temperature / sampling

Contrôle le hasard du choix des tokens ; même à temperature 0, la sortie n’est pas garantie byte-identique. Controls randomness in token selection; even at temperature 0, output is not guaranteed byte-identical.
Documentation officielleOfficial documentation ↗

Non-determinism

Deux appels identiques peuvent différer légèrement ; les tests doivent vérifier structure ou faits, pas une chaîne exacte. Two identical calls can differ slightly; tests should assert structure or key facts, not an exact string.
Documentation officielleOfficial documentation ↗

Model tiers

Gammes de modèles (capacité vs coût / latence) ; choisir le tier selon la difficulté de la tâche. Model families trading capability vs cost/latency; match the tier to task difficulty.
Documentation officielleOfficial documentation ↗

max_tokens

Plafond de tokens de sortie pour un appel ; ne réduit pas le coût d’entrée ni la taille de l’historique. Cap on output tokens for a call; it does not cut input cost or shrink conversation history.
Documentation officielleOfficial documentation ↗

Visual tokens

Coût des images en tokens, qui croît avec les dimensions ; le plafond dépend du tier de modèle. Image cost in tokens that scales with dimensions; the ceiling varies by model tier.
Documentation officielleOfficial documentation ↗

System prompt

Emplacement durable, conventionnellement le plus fiable, pour rôle, ton et règles stables face aux tours utilisateur suivants — sans garantie de priorité absolue. Durable, conventionally most reliable home for role, tone, and stable rules against later user turns — not an absolute-priority guarantee.

Zero-shot

Tâche décrite sans exemple travaillé ; les instructions peuvent rester détaillées. Task described with no worked examples; instructions can still be detailed.
Documentation officielleOfficial documentation ↗

Single-shot

Exactement un exemple travaillé dans le prompt pour ancrer le format ou le comportement attendu. Exactly one worked example in the prompt to anchor the expected format or behaviour.
Documentation officielleOfficial documentation ↗

Few-shot / multi-shot

Plusieurs exemples dans le prompt pour guider le format ou le raisonnement sur cet appel (coût tokens) — sans fine-tuner le modèle. Several examples in the prompt to shape format or reasoning on that call (at token cost) — does not fine-tune the model.
Documentation officielleOfficial documentation ↗

Output constraint

Règle explicite sur la forme de la sortie (JSON, longueur, pas de préambule) — distincte des exemples few-shot. Explicit rule on output shape (JSON, length, no preamble) — distinct from few-shot examples.

Prompt caching

Réutilise un préfixe stable à coût réduit ; le cache expire et seul le préfixe inchangé en bénéficie. Reuses a stable prefix at reduced cost; caches expire and only the unchanged prefix benefits.

Point de cache sur un segment ; placez le contenu stable avant le dynamique pour maximiser les hits. Cache mark on a segment; put stable content before dynamic content to maximize hits.

Context engineering

Concevoir quoi mettre dans la fenêtre : chunks, compaction, isolation des sous-contextes. Designing what enters the window: chunking, compaction, and isolated sub-contexts.

RAG

Retrieval-Augmented Generation : récupérer des passages puis générer en s’y appuyant, idéalement avec citations vérifiées. Retrieval-Augmented Generation: fetch passages then generate grounded answers, ideally with validated citations.

Chunking

Découper les documents en passages cohérents pour un retrieval précis, plutôt qu’un document entier. Splitting documents into coherent passages for precise retrieval instead of whole-document chunks.

Context compaction

Libérer la fenêtre : prune/summarize applicatif de l’historique et des tool outputs obsolètes, et/ou compaction de contexte côté plateforme/API quand elle est disponible. Reclaim window budget via app-side prune/summarize of stale history and tool outputs, and/or platform/API context compaction when available.

Streaming / message_stop

Événements SSE pour la sortie progressive. La fin du flux HTTP n’égale pas un message complet : n’écrivez le tour en historique qu’après message_stop ; jetez les tours partiels si interruption. SSE events for progressive output. HTTP stream end is not message completion: commit a turn to history only after message_stop; discard partial turns on interruption.

Structured outputs / JSON schema

Schéma JSON côté API pour contraindre la forme de la réponse. Distinct des tool schemas stricts, qui valident les arguments d’outils — les deux remplacent le formatage « prompt only ». API-side JSON schema to constrain response shape. Distinct from strict tool schemas, which validate tool arguments — both beat prompt-only formatting.

Extended thinking

Mode manuel de raisonnement interne avec budget_tokens. En multi-turn, renvoyez les thinking blocks inchangés. Sur les modèles récents, souvent remplacé / déprécié au profit d’adaptive thinking. Manual internal-reasoning mode with budget_tokens. In multi-turn, return thinking blocks unchanged. On newer models, often superseded / deprecated in favor of adaptive thinking.

Adaptive thinking

thinking.type: "adaptive" — le modèle décide quand et combien raisonner ; la profondeur se pilote via effort (pas un budget_tokens fixe). Idéal pour mélanger appels triviaux et difficiles. thinking.type: "adaptive" — the model decides when and how much to reason; depth is steered via effort (not a fixed budget_tokens). Fits mixed trivial and hard calls.
