=== Q1 | domain: LLM Fundamentals | pick: 1 | section: A ===
Two runs of the same prompt at temperature 0 return slightly different wording. Which explanation is correct?
A) Sampling can still introduce variation; temperature 0 favours the likeliest tokens but does not hard-guarantee identical output
B) This is impossible at temperature 0, so one of the two calls must have silently used a different model version or returned a cached response from an earlier request
C) Streaming was left on for one of the calls
D) The two calls used different context windows
Correct: A
Why: Even at temperature 0, determinism is not guaranteed. The long option asserts a false impossibility; streaming and window size do not explain wording variation.

=== Q2 | domain: Prompt Engineering | pick: 2 | section: A ===
Which TWO statements about prompting modes are accurate? (Pick 2)
A) Single-shot includes exactly one worked example
B) Multi-shot examples guide the output on that call, at extra token cost
C) Zero-shot always outperforms few-shot once the task is well-specified
D) Multi-shot permanently fine-tunes the model on the examples
Correct: A, B
Why: Single-shot is one example; multi-shot adds several to shape output per call at token cost. Examples do not fine-tune the model, and zero-shot is not universally superior once specified.

=== Q3 | domain: API Mechanics | pick: 1 | section: A ===
A multi-turn session grows until a request exceeds the window mid-generation. What happens?

B) The request is silently accepted and the model drops whichever earlier turns it judges least relevant to make room for the rest
C) The window auto-expands for that call

=== Q4 | domain: Model Selection | pick: 1 | section: A ===
You have many trivial calls and occasional hard ones, and want to pay for deep reasoning only when it helps. Which fits?
A) Adaptive thinking, with effort scaled to the task
B) Extended thinking pinned to maximum effort on every call, so quality is never at risk on the genuinely hard ones
C) Fast mode on every call
D) A larger model tier for all calls
Correct: A
Why: Adaptive thinking spends reasoning effort only where it changes the answer. Always-max overpays on trivial calls, fast-mode-everywhere underserves the hard ones, and a bigger tier does not target the mix.

=== Q5 | domain: Cost & Tokens | pick: 1 | section: A ===
A large, stable system prompt is sent on every call in a high-volume app. What does prompt caching do, and what is its limit?
